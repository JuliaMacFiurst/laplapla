# Starter PDF: публикационный контракт V1

Каталог уже различает `offerTier: "starter_pdf" | "full_adventure"`, `format: "pdf"` и `delivery: "private_pdf_download" | "account_print_builder"`. Sound Case остаётся `full_adventure` с печатью из аккаунта. Статус `draft` исключает товар из публичного каталога и страницы товара. Сейчас Starter PDF в каталоге нет.

Для первого реального Starter PDF подготовить:

1. Проверенный PDF на RU / EN / HE или явно указанные доступные языки, длительность 15–25 минут, возраст, результат занятия, содержимое, действия взрослого и права на использование. Файл должен храниться приватно; в публичный каталог не помещать прямой URL.
2. Утверждённую цену в копейках/агоротах и учётное описание. Не копировать цену Sound Case.
3. Серверный манифест соответствия `product_id → private storage key`, проверку активного entitlement и короткоживущую ссылку на скачивание. Проверить выдачу после оплаты и повторный доступ из аккаунта.
4. Расширение существующего PayPal checkout, который сейчас принимает только `sound-case-001`, и маршрутов checkout/success под ID нового товара. Использовать тот же механизм заказов, PayPal capture, идемпотентную финализацию, entitlement, квитанции и возвраты.
5. Отдельное описание Starter PDF из полей каталога. Текущая подробная страница жёстко оформлена под Sound Case, поэтому нельзя переводить новый товар в `coming-soon` или `active` до её подключения. После теста доставки и локализаций сменить `draft` на `active`.

Не считать PDF квитанции материалами продукта: текущая квитанция и тестовое PDF-подтверждение оплаты являются отдельными документами.

## Воронка

После применения миграции `20261110111649_shop_promo_funnel_events.sql` показатели баннера доступны в существующем отчёте `commerce_analytics_report_v1` и во вкладке `/admin/analytics → Commerce Analytics`:

```sql
select public.commerce_analytics_report_v1(
  '2026-11-10T00:00:00Z', '2026-11-11T00:00:00Z', 'live'
);
```

Поле `promotions` содержит по каждому `product_id` показы и нажатия баннера, а также отдельные числа уникальных посетителей и сессий. Прежний `funnel.entry_points.home_promo` означает исторические события `product_interest` с прямым переходом в checkout; новые нажатия в него не включаются. `checkout_starts` берётся из созданных заказов, `paid_orders` — из уникальных подтверждённых заказов по `paid_at`. Показатели независимы, не образуют последовательную когорту и не дают процентов перехода. Сырые события обычно удаляются примерно через 15 дней. Трафик не сегментирован на Live/Sandbox; коммерческие заказы сегментированы.
